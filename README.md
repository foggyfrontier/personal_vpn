# personal_vpn

Личный VPN для обхода блокировок в РФ на базе **Xray (VLESS + Reality)**.
Запускается в Docker и управляется через Portainer.

## Как это работает

```
Телефон ──(выглядит как HTTPS к www.samsung.com / ya.ru / ...)──▶ Сервер в NL, порт 443 ──▶ Интернет
                                                                   │
                                                    сортировщик по SNI
                                                   ┌───────┼────────┐
                                             Reality-вход  Reality-вход  ... (по одному на сайт)
```

- **Xray**: программа-сервер, которая принимает зашифрованный трафик от твоих
  устройств и выпускает его в интернет уже из Нидерландов.
- **VLESS**: протокол, по которому клиент и сервер общаются. Он очень лёгкий
  и сам по себе ничего не маскирует.
- **Reality** отвечает за маскировку. Провайдер (и его DPI) видит обычное
  TLS-соединение с каким-нибудь сайтом, например `www.samsung.com`. Если
  кто-то попробует «прощупать» сервер, не зная ключа, Xray честно
  перенаправит его на настоящий сайт, и сервер будет неотличим от обычного
  прокси к нему. Поэтому Reality сейчас блокируют гораздо хуже, чем
  WireGuard или OpenVPN.
- **Несколько сайтов сразу.** DPI у разных операторов режет разные сайты
  маскировки. Поэтому сервер принимает сразу несколько: на порту 443 стоит
  «сортировщик», который смотрит, какой сайт указал клиент, и передаёт
  соединение нужному Reality-входу. Для каждого сайта у устройства своя
  ссылка, а приложение само проверяет, какая из них работает.
- **Ключи.** У сервера есть приватный ключ (хранится только на сервере) и
  публичный (зашит в ссылку клиента). У каждого устройства свой UUID, это
  как личный пароль. Одно устройство можно отключить, не трогая остальные.

### Про белые списки

В режиме белых списков доступны только разрешённые адреса, а IP сервера в
Нидерландах в них нет. Никакой протокол тут не поможет: до сервера просто
не дойти. Обходить это будем отдельным этапом, через промежуточный сервер
в РФ (см. «Планы»).

## Файлы

| Файл | Что это |
|---|---|
| `scripts/setup.sh` | Генерирует ключи, конфиг сервера и ссылки для устройств. При повторном запуске пересобирает конфиг и сохраняет ключи |
| `scripts/diagnose.sh` | Самопроверка: подключается к VPN с самого сервера и показывает, работает ли сервер |
| `docker-compose.yml` | Стек для Portainer, который запускает Xray |

## Установка

Все команды выполняются **на сервере по SSH** (`root@physical-aquamar`), не в контейнере.

### 1. Скачать скрипт и запустить его

```bash
mkdir -p /opt/xray && cd /opt/xray
nano setup.sh        # вставить содержимое scripts/setup.sh, сохранить: Ctrl+O, Enter, Ctrl+X
bash setup.sh
```

Скрипт проверит сайты маскировки из списка (подходят только сайты с TLS 1.3
и HTTP/2), создаст `/opt/xray/config.json` и выведет для каждого устройства
(по умолчанию `android`, `windows`, `iphone`) **блок ссылок `vless://...`,
по одной на каждый сайт**. Если контейнер `xray` уже запущен, скрипт сам
его перезапустит.

Ссылки сохраняются в `/opt/xray/clients.txt`, посмотреть их снова можно
командой `cat /opt/xray/clients.txt`.

Список сайтов лежит в `/opt/xray/targets.txt`. Чтобы его поменять,
отредактируй файл (`nano /opt/xray/targets.txt`) и снова запусти
`bash setup.sh`. Ключи при этом сохранятся, и уже работающие ссылки
продолжат работать.

> ⚠️ Ссылка `vless://` — это ключ доступа к твоему VPN. Не публикуй её и не
> коммить в репозиторий.

### 2. Запустить Xray в Portainer

1. Portainer → **Stacks** → **Add stack**.
2. Имя: `xray`.
3. **Web editor**: вставить содержимое `docker-compose.yml`.
4. **Deploy the stack**.
5. Открыть контейнер `xray` → **Logs**. Ошибок быть не должно.

Проверка на сервере: `ss -tlnp | grep ':443 '` должна показать, что порт слушает `docker-proxy`.

### 3. Подключить устройства

| Устройство | Приложение |
|---|---|
| Android | **v2rayNG** или **Hiddify** (Google Play / GitHub) |
| Windows | **v2rayN** или **Hiddify** (GitHub) |
| iPhone | **v2RayTun**, **Streisand** или **Hiddify** (App Store) |

1. Скопируй **весь блок ссылок** своего устройства из вывода скрипта.
   Удобно отправить его себе в Telegram («Избранное») и скопировать уже на телефоне.
2. В приложении нажми **＋ → «Импорт из буфера обмена»**. Появится несколько
   серверов, по одному на каждый сайт.
3. Запусти проверку всех серверов:
   - **v2rayNG**: меню ⋮ → «Проверка реальной задержки всех» (Real delay all), потом «Сортировать по результату».
   - **v2RayTun / Streisand / Hiddify**: кнопка пинга или теста у группы серверов.
4. Выбери сервер с наименьшей задержкой (без ошибки) и подключись.
5. Проверь: https://ipinfo.io должен показывать страну `NL`.

Если какой-то вариант потом перестанет работать, просто выбери другой из списка.

## Если не работает

- **Сначала самопроверка**: `bash diagnose.sh`. Если с сервера всё ✓, а с
  телефона не работает, значит, соединение режут по дороге из РФ, а не
  ломается сервер.
- **Контейнер перезапускается**: смотри Logs в Portainer, чаще всего причина в ошибке в `config.json`.
- **В логе `REALITY: processed invalid connection ... failed to read client hello`**:
  соединение до сервера доходит, но первый TLS-пакет (в нём указан SNI) по
  дороге выбрасывает DPI оператора. Попробуй в приложении ссылки с другими
  сайтами. Если не работает ни одна, добавь новые сайты в
  `/opt/xray/targets.txt`, запусти `bash setup.sh` и импортируй новые ссылки.
- Подробный лог для диагностики: в `/opt/xray/config.json` поставь
  `"loglevel": "info"`, выполни `docker restart xray && docker logs -f xray`.
- **Не подключается совсем**: проверь, что порт 443 не закрыт файрволом хостинга (Aeza → панель сервера).
