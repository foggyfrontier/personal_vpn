# personal_vpn

Личный VPN для обхода блокировок в РФ на базе **Xray (VLESS + Reality)**.
Запускается в Docker и управляется через Portainer.

## Как это работает

```
Телефон / ноутбук ──(выглядит как HTTPS к www.microsoft.com)──▶ Сервер в NL (Xray, порт 443) ──▶ Интернет
```

- **Xray**: программа-сервер, которая принимает зашифрованный трафик от твоих
  устройств и выпускает его в интернет уже из Нидерландов.
- **VLESS**: протокол, по которому клиент и сервер общаются. Он очень лёгкий
  и сам по себе ничего не маскирует.
- **Reality** отвечает за маскировку. Провайдер (и его DPI) видит обычное
  TLS-соединение с `www.microsoft.com`. Если кто-то попробует «прощупать»
  сервер, не зная ключа, Xray честно перенаправит его на настоящий сайт
  Microsoft, и сервер будет неотличим от обычного прокси к нему. Поэтому
  Reality сейчас блокируют гораздо хуже, чем WireGuard или OpenVPN.
- **Ключи.** У сервера есть приватный ключ (хранится только на сервере) и
  публичный (зашит в ссылку клиента). У каждого устройства свой UUID, это
  как личный пароль. Одно устройство можно отключить, не трогая остальные.

### Про белые списки

В режиме белых списков доступны только разрешённые адреса, а IP сервера в
Нидерландах в них нет. Никакой протокол тут не поможет: до сервера просто
не дойти. Обходить это будем отдельным этапом, через промежуточный сервер
в РФ (см. «Планы»).

## Файлы

| Файл | Что это |
|---|---|
| `scripts/setup.sh` | Один раз генерирует ключи, конфиг сервера и ссылки для устройств |
| `scripts/set-target.sh` | Меняет сайт, под который маскируется Reality, не трогая ключи |
| `docker-compose.yml` | Стек для Portainer, который запускает Xray |

## Установка

Все команды выполняются **на сервере по SSH** (`root@physical-aquamar`), не в контейнере.

### 1. Скачать скрипт и запустить его

```bash
mkdir -p /opt/xray && cd /opt/xray
nano setup.sh        # вставить содержимое scripts/setup.sh, сохранить: Ctrl+O, Enter, Ctrl+X
apt install -y qrencode   # по желанию: чтобы видеть QR-коды для телефона
bash setup.sh
```

Скрипт создаст `/opt/xray/config.json` и выведет по ссылке `vless://...` для
каждого устройства (по умолчанию `android`, `windows`, `iphone`). Ссылки
сохраняются в `/opt/xray/clients.txt`, посмотреть их снова можно так:
`cat /opt/xray/clients.txt`.

> ⚠️ Ссылка `vless://` — это ключ доступа к твоему VPN. Не публикуй её и не
> коммить в репозиторий.

### 2. Запустить Xray в Portainer

1. Portainer → **Stacks** → **Add stack**.
2. Имя: `xray`.
3. **Web editor**: вставить содержимое `docker-compose.yml`.
4. **Deploy the stack**.
5. Открыть контейнер `xray` → **Logs**. Ошибок быть не должно.

Проверка на сервере: `ss -tlnp | grep ':443 '` должна показать, что порт слушает `docker-proxy`.

### 3. Подключить устройства

| Устройство | Приложение |
|---|---|
| Android | **v2rayNG** или **Hiddify** (Google Play / GitHub) |
| Windows | **v2rayN** или **Hiddify** (GitHub) |
| iPhone | **v2RayTun**, **Streisand** или **Hiddify** (App Store) |

В приложении выбери «Импорт из буфера обмена» (или отсканируй QR-код) и
вставь ссылку этого устройства. Затем подключись и открой, например,
https://ipinfo.io: там должна быть страна `NL`.

## Если не работает

- **Контейнер перезапускается**: смотри Logs в Portainer, чаще всего причина в ошибке в `config.json`.
- **В логе `REALITY: processed invalid connection ... failed to read client hello`**:
  соединение до сервера доходит, но первый TLS-пакет (в нём указан SNI) по
  дороге выбрасывает DPI оператора. Смени сайт маскировки:
  `bash set-target.sh --check сайт1 сайт2` проверит, подходят ли сайты,
  а `bash set-target.sh сайт` применит выбранный. После этого поменяй SNI
  на устройствах.
- Подробный лог для диагностики: в `/opt/xray/config.json` поставь
  `"loglevel": "info"`, выполни `docker restart xray && docker logs -f xray`.
- **Не подключается совсем**: проверь, что порт 443 не закрыт файрволом хостинга (Aeza → панель сервера).
